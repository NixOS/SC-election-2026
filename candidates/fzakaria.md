#### What I have done

This is only a small list of my contributions to the Nix ecosystem, which I love.

- [trynix](https://trynix.dev/) a site that lets you run any nixpkgs package instantly in the browser via WASI.
- [nixmultiverse](https://nixmultiverse.com/) a tool to let you install any historical version of any nixpkgs package; fast-mode skips evaluation and goes straight to the store path.
- [grail](https://fzakaria.github.io/grail/) a way to describe version ranges for software via a closed form syntax across 14 years of nixpkgs
- [omniflake](https://omniflake.com/) tooling for managing a 16,000+ flake universe.
- [omnibin](https://omnibin.dev/)  "every package is already installed": on-demand package execution without installs.
- [guix-transfer](https://github.com/fzakaria/guix-transfer) a way to import Guix derivations into Nix
- $ORIGIN / relocatable-binaries support with the Linux kernel community to further Nix
- Regular long-form writing on Nix internals and advanced concepts at https://fzakaria.com
- Co-organized https://tacosprint.org/ with [Domen](https://www.domenkozar.com/)
- [Nix auto follow](https://github.com/fzakaria/nix-auto-follow) - a way to have all yoru flakes follow each other.
- Maintainer of a few Nixpkgs packages
- Contributed to CppNix upstream and use to attend the weekly meetings.

#### What I will do

- <ins>Prioritize Linux</ins>. Nix's future is on Linux. I will push for development to prioritize the Linux ecosystem above others (Windows, BSD, and macOS).
- Improve Nix to work well with AI-assisted development.
- Keep Nix powerful. Laziness, the store model, and the sharp edges are Nix's superpower. I will resist efforts to sand off the power that power users came for in the name of approachability. Approachability should come from better tooling and docs, not a weaker model.
- Fix upstream, not around it. Too much of nixpkgs is accumulated workarounds for problems that live one layer down. Rebuild the world if necessary!
